# dsh-calibration-tier 使用说明

> 给 DSH（DeepSeek Harness）输入框加一条档位条：**五种模式（思考 / 循环 / 对抗 / 检索 / 代理）+ 三个强度档**，用来控制模型「动手前问多深、交付后磨几轮、要不要额外再审一遍、要不要去找技能、要不要把活派给子代理并换模型」。
> 版本：3.5.0（简称 CT，包名 `dsh-calibration-tier`）　适用：DSH Desktop / DSH NEXT（带 Web 客户端插件支持的版本）

---

## 一、它解决什么问题

用 AI 干活时常见两种翻车：

- **不问就冲**：方向理解错了，做完才发现要重来；
- **问个没完**：一句「把这个文件删了」被追问五轮；
- 或者**交付完就结束**：只在这台机器/这个场景能用，换个环境就坏。

这条档位条把「用力程度」做成可以随时拨的三档，并把「循环打磨」「对抗审查」「检索找技能」「派子代理」做成可叠加的开关：

| 你想要 | 拨成 |
|---|---|
| 别问了，直接做 | 思考 · 常规 |
| 正常做，但先对一下方向 | 思考 · 严格（默认） |
| 这事重要，先问清楚再动手，做完还要被挑刺 | 思考 · 极致 |
| 做完了还要反复打磨到收敛 | 循环 · 交付 / 极致 |
| 想法可能只在当前场景成立，需要有人唱反调 | 任意模式 + 对抗 |
| 手上的技能可能不够用，想找更合适的 | 任意模式 + 检索格点到「增量 / 全量」 |
| 想让子代理按模块用不同模型、还要有人独立挑刺 | 任意模式 + 代理格点到「效率 / 性能」 + 对抗 |

## 二、界面长什么样

```
思考：  [常规] [严格] [极致] ‖ [循环] [对抗] ‖ [本地] [默认]
循环：  [轻量] [交付] [极致] ‖ [循环]亮 [对抗] ‖ [本地] [默认]
循环+对抗：[轻量] [交付] [极致]橙 ‖ [循环]亮 [对抗]亮
检索格：点一下 本地 → 增量 → 全量 → 本地 …（末尾第一格，v3.5.0）
代理格：点一下 默认 → 效率 → 性能 → 默认 …（末尾第二格，v3.5.0）
```

隔离线左边是**强度三档**，中间两个开关，**末尾两个可以点着轮换的格子**：

- **循环**：切换模式。前三格的含义从「问多深」变成「磨几轮」，标签一起变；
- **对抗**：叠加开关，不改变前三格。打开后，模型每轮会多做一遍对抗审查；
- **检索**：末尾第一个格子，点一下 **本地 → 增量 → 全量 → 本地**。「本地」= 不联网检索、只用已装技能（也就是这个开关的关），所以没有再单独一个开关格；
- **代理**：**强化**开关。末尾第二个格子，点一下 **默认 → 效率 → 性能 → 默认**。「默认」= 不派子代理、不强化：派活也沿用主模型（不指定更强模型、不改白名单）；点到效率/性能后，模型按模块（派活 / 评审 / 对抗 / 检索）自动挑更强的模型；对抗还会强制换一家 provider 来避免「自己审自己」；
- **颜色常亮**：这两格三档都上色——「本地」也保持天蓝、「默认」也保持墨绿，颜色表示「这是检索 / 代理那一维」，当前是哪一档看文字；
- **同开转橙**：循环和对抗同时亮起时，左边三格的选中格由绿转橙（红 + 绿 中和），一眼看出这一轮是「边磨边审」；循环开关仍绿、对抗开关仍红。

按钮上基本没有悬停解释（2026-10-24 起只留按钮本体），只有两个轮换格带一句「点一下切到哪」。忘了就看这张表。

### 代理三档（末尾第二格轮换）

| 档 | 怎么挑模型 |
|---|---|
| 默认 | **不派子代理、不强化**：`agent_delegate` 不挑更强 route，直接沿用主模型的 provider/model；只有拿不到主模型信息时才退回效率档挑并说明 |
| 效率 | **强化一档 + 性价比**：候选只留比主模型分高的，再挑其中最便宜的那一档（够用就停），同档里分最高、同分取代价低的。主模型已是上限时如实标「未升级」，沿用主模型。池里可能包含免费线（`buddy` / `workbuddy` 这类），**免费线不稳时会静默失败**——收到 `failed` 通知就按返回的 `fallbackRoute` 重派一次；同分时免费线排在官方/自配之后（能力分更高照样能选中；手动点名不受影响）。名单可改：`calibration-models.json` 顶层写 `{ "providers": { "buddy": false, "my-free-channel": true } }`，下一个请求就生效 |
| 性能 | **绝对质量**：全池按领域分挑最高的，配模型声明的最高推理等级；挑不到就沿效率档 → 主模型自审降级。适合重要任务 |

### 强度三档（思考模式）

| 档 | 模型会做什么 |
|---|---|
| 常规 | 按平时标准直接做：不锚定、不复述、不提问 |
| 严格（默认） | 复述目标 + 2 个确认点（从歧义点里挑）+ 一句风险（逆向 pre-mortem）+ 假设清单 + 回滚/验收/失败分支 |
| 极致 | 严格全部，再加 6 条覆盖轴逐条、反证与反例、对抗自检、对抗复审、止损线 |

**思考强度按档位分配**（v2.3.0）：三张清单随档位发下来——**歧义点**（严格 2 / 极致 3：目标与验收、不可逆与外部动作、范围与取舍，只有会改变执行的才问）、**覆盖轴**（严格 3 / 极致 6：正常路径 / 边界与空值 / 失败与回滚 / 依赖与副作用 / 成本与性能 / 后续与可维护）、**逆向**（严格 1 / 极致 3：pre-mortem、反证、反例）。**循环模式不例外**：轻量 = 常规、交付 = 严格、极致 = 极致，所以在循环档里也会先问歧义、再动手。

### 打磨三档（循环模式）

| 档 | 轮次上限 | 评审方式 |
|---|---|---|
| 轻量 | 3 轮 | 纯自检 |
| 交付 | 5 轮 | 第 2 轮一次独立评审 + 收敛轮复核 |
| 极致 | 8 轮 | 第 2 轮起每轮独立评审 |

### 检索三档（末尾第一格轮换）

| 档 | 做什么 | 联网 |
|---|---|---|
| 本地 | 不联网检索，只用已装技能；命中隐藏技能会先 `read` 它的说明 | 不联网 |
| 增量 | 联网找已装之外能用的技能，只读文本不安装，落到暂存目录等你自己定 | 联网 |
| 全量 | 地毯式找一遍，重合的两个技能会做差异分析并出「判别卡」；只跑首轮，不跟循环叠加 | 联网 |

三个值是**一个格子轮着切**的：点一下从「本地」到「增量」、再点一下到「全量」、再点一下回到「本地」。状态里记的仍是「检索开/关 + 两档」，所以关掉再打开不会丢档位记忆（关 = 本地，再点一下从增量开始）。

找回来的技能一律先进暂存目录，任务结束后会问你要「转正 / 放待机库 / 删掉」，不会自己装。

### 对抗开关

| 当前模式 | 对抗审跑在哪 |
|---|---|
| 思考 + 对抗 | 动手前审方案、交付前审改动 |
| 循环 + 对抗 | 每轮审改动 |
| 对抗关 | 不跑，行为和没装这个开关一样 |

### 代理与 agent_delegate（v3.1.0 起，v3.2.2 补齐运行期兜底）

官方 `subagent` 的模型白名单在**会话创建时**就定死了，改配置只对新会话生效。所以想让「当前这个对话」就用上你自配的 API，用 `agent_delegate`：

- 只需要说清任务和模块（派活 / 评审 / 对抗 / 检索），模型自动挑；
- 也可以点名要哪个模型（provider + model）；
- 它**不受白名单限制**，代价是没有额度护栏——批量跑之前先估一下成本。
- **启动期失败会自动回退**：预检或启动失败时换官方 deepseek 模型重试一次，返回第一句就是「⚠️ 已回退」，告诉你是谁不可用、退到了哪。
- **运行期失败要自己重派**：子代理启动成功、跑一半挂掉（例如 `404 page not found`、额度用尽），工具没法自己等异步结果，所以返回里带 `fallbackRoute`（官方兜底 route）。收到 `failed` 通知时，主模型会用 `provider=…&model=…` 重派一次并告诉你「自配失败，已用官方兜底」。
- **推理等级只在模型声明了才传**：性能档取该模型声明的最高档、效率档取模型默认档（升了模型就不再砍强度）；没声明就一个都不传（v3.2.1 起，避免把「没声明 efforts」误判成「不可用」）。
- **代理关 = 不强化**：`agent_delegate` 不挑更强 route，直接沿用主模型的 provider/model；只有拿不到主模型信息时才退回按效率档挑，并在文本里说明。
- 还能选运行时：`spawn`（默认，能换模型）/ `claude-code` / `codex`（用它们各自的 CLI 与登录态，模型由 CLI 配置决定，不能在这里切）。

**对抗 v2（2026-10-28 起）**：代理开着时，对抗由**另一个模型**在**独立会话**里做，只看你的需求和产物文件，不看主模型怎么想；报告里会写「审者模型 / 隔离度」。查三件事：来源靠不靠谱（权威性）、数字引用有没有出处（真实性，会用工具机械核对文件行号与域名）、还有没有没覆盖到的坏场景（全面性）。**代理关着就退回主模型自审，报告会标「隔离度：低」**——别把自审当隔离审。

条数随档位：常规/严格 3 条、极致 5 条。

## 三、安装

### 1. 拿到文件夹

把整个 `dsh-calibration-tier` 文件夹放到任意目录（例如 `D:\Tools\dsh-calibration-tier`）。文件夹里应有 `package.json`、`lib\`、`cordis.patch.yml`。

### 2. 跑安装脚本

```powershell
pwsh -File .\install-profile.ps1
```

脚本会做三件事（每一步都会打印，并先备份 profile 的 `package.json`）：

1. 在 profile 的 `dependencies` 里加一条 `link:` 依赖，指向这个文件夹；
2. 把包名 `dsh-calibration-tier` 追加进 `dsh.profile.bundles`；
3. 在 profile 的 `node_modules` 下建链接（Windows 用 junction）。

想看它要做什么而不落盘：`pwsh -File .\install-profile.ps1 -WhatIf`。

### 3. 完全退出并重开 DSH

关窗口不够，要**退出进程**再启动。重开后输入框工具行（模型选择左边）会出现这条档位条，默认停在「严格」。

> 装不上时：确认 DSH 版本带 Web 客户端插件支持；`node_modules` 链接需要能创建 junction（普通用户即可，不需要管理员）。

## 四、模型怎么读到你的选择

档位条不直接改模型，它通过两个工具把「当前设置」告诉模型：

| 工具 | 作用 |
|---|---|
| `clarify_tier` | 两种模式都返回思考强度（常规/严格/极致，含**歧义点 / 覆盖轴 / 逆向**三张清单）+ 对抗开关 + 检索开关与口径 + 代理开关与路由计划 |
| `forge_level` | 循环模式返回打磨档（轻量/交付/极致）+ 轮次 + 同档位思考强度 + 对抗 / 检索开关状态 |
| `verify_claims` | 机械核对「断言 ↔ 来源」：文件行号与数字/引号短语是否对得上、URL 域名分级；只证明「有对应源」，不证明源本身真实（只读、纯本地） |

配套技能（仓库 `skill\` 目录里）：

- `clarify-needs`：拿到档位后「怎么问」（复述/确认点/设计树/共识摘要）；
- `counter-review`：对抗开关打开后「怎么唱反调」（六轴场景矩阵、每条攻击必须带检查方法）。

**循环模式的打磨技能 `loop-forge` 不随本插件安装**，需要另装到技能目录。装好后再开「循环」，模型才会按「判据 → 每轮报数 → 自动止损」的流程走；没装也能用，只是不会自动多轮打磨。

## 五、几个细节

- **每轮一份快照**：一条消息 = 一轮。开工时读取的档位会在本轮固定；本轮内再拨档位条，只影响下一轮——条尾会出现一个小圆点表示「已改、下轮生效」。
- **每个对话各用各的**：设置按会话存，互不影响；新对话继承默认（思考 · 严格）。
- **状态存在本地**：`<DSH_HOME>\storages\calibration.json`（DSH_HOME 一般是 `C:\Users\<你>\.dsh`）。
- **能力分与免费线名单可覆盖**：`<DSH_HOME>\storages\calibration-models.json` —— `{ "models": { "provider/model": { "code": 9, "free": false } }, "providers": { "buddy": false } }`；单项 `free` 优先于 `providers` 名单，改完下一个请求生效（不用重启）。
- **离线也能用**：控件连不上后台时显示 `!`，改动只存本地，恢复后自动同步。

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 重开后没看到档位条 | 只是关了窗口没退出进程；或 profile 里没写上（重跑安装脚本看输出） |
| 拨了档位但模型没变化 | 让模型「调一次 clarify_tier / forge_level」；模型每轮开工读一次 |
| 开了「循环」没看到多轮打磨 | 没装 `loop-forge` 技能；或已收敛（判据全过、无新增） |
| 开了「对抗」但没看到对抗审段落 | 该轮没有可审的改动；或已达条数上限；极端简单任务会跳过 |
| 同时装了两套 DSH，控件显示另一套的值 | 刚打开、本会话还没被写过时会有几秒`!`状态；发一条消息或切回窗口即自动认准 |
| 端口被占（三套以上同开） | 控件退化为只读（虚线 + `!`）：本地还能拨，但不同步 |
| 怎么卸载 | 见下一节 |

## 七、卸载

```powershell
pwsh -File .\install-profile.ps1 -Uninstall
```

然后删掉 `<DSH_HOME>\storages\calibration.json`，重开 DSH。

## 八、能做什么、不做什么

**能**：改模型每轮的工作强度；循环模式下自动多轮打磨；对抗模式下逐条挑毛病并要求给出检查方法。

**不能**：保证结果正确、替你做决策、联网查资料。它只调「用力程度」，不是质量保险。

**隐私**：本地 HTTP 桥只绑 `127.0.0.1`，没有 token，同机其它进程可以读写——这台机器的信任边界就是你自己。

## 九、版本

当前 3.5.0（2026-10-29：检索与代理各收成一个轮换格——「本地 → 增量 → 全量」「默认 → 效率 → 性能」，主条固定 11 个节点、不再随开关增减，宽窄屏同形；3.4.0 定「代理=强化」语义——关=不强化沿用主模型、效率=强化一档且同分取代价低的、性能=绝对质量+最高推理等级；3.3.1 修 `domain=writing/toolUse` 计分恒空、counter 同族假隔离、补 `contextWindow` 采集；3.3.0 免费线名单改为配置文件可增删；3.2.3 效率档不再让免费线在同分时抢走自动挑模型；3.2.2 修自配 Anthropic 的 `baseURL` 双 `/v1`（运行期 404）并补 `fallbackRoute` 运行期兜底）。变更记录见仓库 `CHANGELOG.md`，发布说明见 `docs/release-notes.md`。
