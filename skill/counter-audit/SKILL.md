# 对抗审 · counter-audit（v2）

把「评委」换成「反对者」，再加两道闸：**来源可核**、**数据不许编**。
不是找「现在错没错」（那是评审），是找「换个环境/换种用法会不会错」，以及「这句话凭什么这么写」。

## 何时开

| 触发 | 动作 |
|---|---|
| `clarify_tier.counter.enabled = true` | 按 `counter.scope` 跑：思考=动手前审方案 + 交付前审改动；循环=每轮 |
| `clarify_tier.agent.on = true` 且 `agent.modules.counter` 有 route | 用该 route 起**独立子代理**审，不要自己审 |
| `agent.on = false`（代理关） | 主模型自审，报告头必须写「隔离度：低」 |
| 用户说「杠我 / 挑刺 / 验真 / 查数据」 | 直接跑，条数听用户的 |

条数由 `counter.maxAttacks` 给出：常规/严格 **3 条**、极致 **5 条**；关着就是 0 条。

## 隔离：三层，缺一层就降级并明写

1. **上下文隔离**：用 `agent_delegate`（fresh 子代理），**不用 `subagent_fork`**。它自己 `read` 产物文件，不接收主代理的推理过程。为什么不用官方 `subagent`：它的白名单在会话创建时快照，当前会话改不了；`agent_delegate` 走 provider 层，`module:"counter"` 会自动避开主模型。
2. **模型隔离**：`agent.modules.counter.provider` 必须 ≠ 主模型 provider；只能同 provider 时至少换 model，并在报告头标「隔离度：中」；主模型自审标「低」。
3. **指令隔离**：只给「挑刺」指令 + 需求原文 + 产物路径 + 声称的证据清单。**禁止**在 prompt 里写「我认为这里没问题，你确认一下」——那等于给结论。

### 调不通怎么办（三级回退）

```
性能档 route（agent.modules.counter）
  └─ 报 route 不允许 / 模型不可用 → 降效率档（agent.fallback.modules.counter）
       └─ 还不行 → 主模型自审，报告头标「隔离度：低」
```

每降一级都在报告里写清降到了哪一级；不许静默降级，更不许把自审写成「已隔离」。

prompt 首行带上回执，便于事后核对用了哪条计划：

```
[CT-plan:<planId> module:counter]
```

## 三查（每查都要落表）

### 查一：权威性

| 级别 | 什么算 | 处理 |
|---|---|---|
| L1 | 一手文档、官方规范、源码、命令输出、你自己跑出来的数 | 可直接支撑结论 |
| L2 | 论文、机构报告、标准 | 可支撑，注明机构与年份 |
| L3 | 二手媒体、博客 | 只能当线索，不得单独支撑结论 |
| L4 | 无名转载、AI 生成、无出处 | 视同未证实 |

URL 类用 `verify_claims` 拿域名分级（L1–L4）；**分级只说明域名类别，不代表内容真实**。

### 查二：真实性（数据不许编）

对每个数字 / 日期 / 人名 / 链接 / 命令 / 引文，逐条走 `verify_claims`：

```json
{"claims":[
  {"text":"退化率 3.2%","source":{"kind":"file","path":"docs/a.md","line":42}},
  {"text":"官方要求 Node ≥22","source":{"kind":"url","url":"https://nodejs.org/en/about/previous-releases"}},
  {"text":"npm test 86 项全过","source":{"kind":"command","snippet":"# pass 86"}}
]}
```

三态收口（不许多于三态）：

- **属实**：有源且锚点命中；
- **无源**：找不到来源 → 交付物里**不许保留**，要么补源要么删；
- **矛盾**：源与断言对不上 → 立即标红，写清冲突点。

`verify_claims` 的能力边界必须一起写进报告：**它只证明「有对应的源」，不证明源本身真实**。所以报告分三栏：「已核（文件/行号命中）」「未核（无源）」「核不了（命令输出等弱证据）」。

### 查三：全面性

原六轴照旧（版本/环境、机器状态、用户用法、数据形态、时序、极端量），再加三轴：

| 轴 | 拷问什么 |
|---|---|
| 数据 | 数字来源、口径、样本量、时间范围；换个口径结论还成立吗 |
| 引用 | 每条外部断言有没有可点的源；引用的是原文还是转述 |
| 逻辑 | 隐含前提、因果倒置、幸存者偏差、以偏概全 |

每条改动至少在一条轴上被拷问；覆盖不到的轴写「Z（未涉及）」，不许留空。

## 每条攻击必须四元组

`隐患 | 触发条件 | 后果 | 检查方法`。缺任意一项 → 作废，不许写进报告。

三态收口：

- **接受** → 挂编号，进本轮改动；
- **驳回** → 给证据（文件:行 / 命令输出 / 文档行），一行写清；
- **转边界** → 记进「已知边界」，写影响范围与代价，不修但说清。

## 循环模式：产物快照

循环中间轮次的产物可能只在对话里，对抗子代理读不到。规则：**开对抗时，每轮结束把产物写到 `tmp/round-<n>.md`**（或交付物路径），对抗只读该文件。没有快照就退回「主模型自审 + 标隔离度低」，不许假装审过。

## 报告头（固定格式）

```
审者模型：<provider>/<model> · 隔离度：高/中/低 · planId：<8 位> · 条数：N/N
未覆盖轴：…
已核 X · 未核 Y · 核不了 Z
```

## 禁止项

- 不许把「没找到问题」写成「通过」——只写「本轮未发现，覆盖轴如下」；
- 不许用主模型自审冒充隔离审；
- 不许在报告里给未核的数字补一个「估算值」；
- 不许引用自己无法指到具体行/URL 的来源。
