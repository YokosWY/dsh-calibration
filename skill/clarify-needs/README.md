# clarify-needs · 需求锚定与拷问

> 动手之前先定档：轻活不打扰，重活问到没有假设。
> 四档：**off 关闭 / low 常规 / high 严格 / max 极致**。
> **独立项目**：仓库 `dsh-clarify-tier` 的 `skill/clarify-needs/`；不并入 Token-Governance（TG）。
> **版本**：v4.0，2026-10-23 起独立发布，随 [dsh-clarify-tier](https://github.com/YokosWY/dsh-clarify-tier) 仓库发版。

- 版本：**v4.0**（四档：删除原 low「方向」，其余降一级）
- 技能名：`clarify-needs`（常驻，模型目录可见）
- 结构：1 个技能 + 2 篇文档 + 变更史

---

## 1. 它解决什么问题

Agent 最贵的开销不是「想太多」，而是**想错了重做**：方向错了 → 全部推倒 → 上下文重放再来一遍。
这类成本通常比任何压缩优化的收益都大一个量级。

| 症状 | 代价 |
|---|---|
| 说法含糊（「整理一下」「优化下」） | 做错方向，全量返工 |
| 方案没想清就开工 | 做到一半发现路不通 |
| 关键假设没人说出来 | 交付时才发现不是用户要的 |
| 只问「要不要」，不问「旧路径留不留」 | 后续步骤全崩 |

本技能把「问清楚」变成**有档位、有提问预算、有停止条件**的流程，而不是靠临场发挥。

## 2. 四档（怎么定量）

| 档 | 语义 | 锚定度 | 必须产出的东西 | 动手条件 |
|---|---|---|---|---|
| **off** | **关闭** | — | 无 | 技能退出，直接做 |
| **low** | 常规（默认） | 80% | 复述 + 2 确认点 + 风险提示 + 假设清单（≤3） | 主路径没有分叉 |
| **high** | 严格 | **95%** | 常规 + 回滚 + 验收 + 失败分支 + 前置检查表 | 每步可执行、可退、可验 |
| **max** | 极致 | 99% | 严格 + 反例与代价 + 对抗自检 + 对抗复审（≥3 条） + 止损线 | 用户确认摘要 |

提问**不设数量/轮次上限**，判停只看「还有没有会改变执行的未知」。

**定档顺序：用户点名 > 滑条 > 自动评分 > 默认 low。**

自动评分四问：

| 问题 | 加分 |
|---|---|
| 要动 ≥2 个对象，或跨目录/跨应用 | +1 |
| 只给目标、没给做法 | +1 |
| 已在纠结「要不要做 / 选哪条路」 | +2 |
| 不可逆（删除 / 覆盖 / 迁移 / 花钱 / 对外） | +2 |

`0 = off，1 = low，2 = high，≥3 = max`，另加三条地板：

- 只要不可逆 → 至少 high
- 不可逆 且 在纠结方向 → max
- 会改动文件/配置/系统的任务 → 最低 low（**off 是技能退出位，只给纯只读**）

**升降档**：说「别问了」→ off；「简单确认下」→ low；「仔细点」→ 升一档；「拷问我」→ max；
中途发现不可逆 → 至少 high；连续两轮在同一缺口上问不出新信息 → 兜底给「默认方案 + 风险 + 回滚」。

## 3. 快速开始

复制或链接本目录到技能目录：

```bash
cp -r skill/clarify-needs "$DSH_HOME/skills/clarify-needs"
```

Windows 也可以直接建 junction（改完源目录即时生效）：

```powershell
cmd /c mklink /J "%USERPROFILE%\.dsh\skills\clarify-needs" "D:\path\to\dsh-clarify-tier\skill\clarify-needs"
```

配了 GUI 滑条（插件 [`dsh-clarify-tier`](https://github.com/YokosWY/dsh-clarify-tier)）时，输入框工具行、模型选择左边会有分段条（关闭 / 严格 / 极致，值域 `off/high/max`），模型通过 `clarify_tier` 工具读档位。

装好后模型目录会出现 `clarify-needs`。它是**常驻**技能（每个请求都在上下文里），
不需要手动触发；要直接切档就说「走 high」「上 max」，说「别问了 / 不用澄清」= off（技能退出）。

## 4. 典型场景

| 场景 | 会走哪档 |
|---|---|
| 「这个文件多大」 | off：不用本技能，直接查、一句话答完 |
| 「把 tmp 里过期下载清一下」 | low：复述 + 2 确认点，然后做 |
| 「帮我把 ~/projects 整理一下」 | low：复述 + 成功标准 + 范围 |
| 「把 home 搬过来」 | high：先查 junction/引用/回滚，再问留不留旧链接 |
| 「这套 token 治理要不要上」 | max：设计树 frontier 逐轮，结束给共识摘要 |
| 同一议题第三次讨论 | max + ADR：把「为什么否掉 A」写进决策记录 |

## 5. max 长什么样

每轮把**整个 frontier**（前置已定的决策）**打包进一次 `ask_user_question` 弹窗**，不再在正文里堆 ❓ 列表：

- 每题 2–4 个选项，首项标（推荐）并写一句代价
- 点选即继续，不要求回长文
- 正文只写「已查到的」和「唯一待定的结论」

三条硬规则：

1. 措辞让「选第一项」等于接受推荐答案。
2. 依赖未定问题的问题属于**下一轮**，不许混进来。
3. **事实我查、决策归你**：能自己查的不问；要调查就派子代理，只有下游问题等它。

能按推荐答案安全推进的，**直接做并标「假设：…」**，不要为了确认而中断会话。

结束条件：**frontier 为空** → 共识摘要（决策 + 理由 + 被否选项）→ 用户确认后才动手。

## 7. 设计取舍（详见 docs/design.md）

| 决定 | 理由 |
|---|---|
| **4 档**（v4.0 删掉原 low「方向」） | 用户反馈多档利用率太低：中间的「抓方向」几乎没人拨，删掉后依次降级——常规 80% / 严格 95% / 极限 99% |
| **档位自带方法**，不再单设 M1–M3 | 档位决定问多深，方法随之确定；两套轴（档位 × 模式）要交叉查表，反而慢 |
| **默认 low（常规）** | 日常「整理/改配置/装东西」落在常规档；off 只给纯只读，防止「别问了」被滥用 |
| **档位可被用户点名** | 定档是模型自评，会错；用户一句话切档比模型算分可靠 |
| **不并入 TG** | TG 只认可度量；本技能拿不出指标，硬合并会破坏 TG 的「1 常驻」结构 |

## 8. 成本

| 项 | 值 |
|---|---|
| SKILL.md | 9.2 KB / 4,341 字符 ≈ **1,100 tokens** |
| 周重放（1 万步量级） | ≈ 12 M tokens |
| 缓存命中时 | ≈ ¥0.25/周（可忽略） |
| 未命中时 | ≈ ¥13/周（最坏情况） |

**真正的成本不是 token，而是多问一轮带来的行为开销**——由档位控制（off/low 少问不问）。

## 9. 已知边界

做不到的

- 无法证明「问对了更省」：这是**不可度量**的收益，只能靠少返工间接体现。
- 定档由模型自评，可能判错；靠用户点名 + 「别问了 / 仔细点」兜底。
- max 可能很长（一次问完 frontier，题数不设上限），用户疲劳时收敛质量会下降；靠「只问决策题 + 每题带推荐」压低负担。
- 档名 `low / high / max` 与推理 effort 同名，容易混淆——文档里已标注「同名不同义」。

不做的

- 不接管方案评审、代码评审。
- 不做成多技能包（必须单技能常驻，否则目录成本上升）。
