# 设计说明

## 为什么是 3 档（v5.0 起）

v2.x 用四档（L0–L3）卡**风险跳变点**；v3.0 换五档卡**锚定度**这条连续轴；v4.0 收到四档（删掉「抓方向」）；
v5.0 再收到三档——因为**档位条只有三格**（现在这三格是 常规 / 严格 / 极致）。文档里留一个滑条拨不到的「常规」，
等于教模型读一个不存在的档：实测就出现过按「常规=复述+2 确认点」执行、而工具只返回 off/high/max 的情况。

| 档 | 锚定度 | 一句话 |
|---|---|---|
| low | 80% | 常规：复述、确认点、假设清单 |
| high | 95% | 严格：步骤、回滚、验收 |
| max | 99% | 极致：没有默认假设 |

三条理由：

1. **能拨到的档才有意义**：档位来自滑条与 `clarify_tier`，三格就是三档；多写一档只会让模型去猜不存在的档。
2. **原来「常规」的三样并入严格**：复述 / 2 个确认点 / 假设清单（≤3）不能丢，它们是锚定的下限，严格档本来也要求这些。
3. **与用户话术对齐**：说「简单确认下」落在 high，说「仔细点 / 拷问我」升 max，不必翻译成编号。

**代价**：默认从 80% 抬到 95%，日常小活的开工成本变高。
对冲：说「别问了 / 不用澄清」本技能整体退出（不占档位），且自动评分只做初判，用户一句话就能切档。

## 为什么「退出」不是一档（v5.1 起最低档改叫常规）

v5.0 把最低档做成 `off 关闭`（技能退出位）。实测滑条第一格几乎没人当「退出」用，而「常规」这个轻档反而有用——v5.1 把第一格换成 `low 常规`（复述 + 2 确认点 + 风险 + 假设清单），「别问了」仍是技能退出，但不再占一个档位。

下面的 v3.0 记录保留原样，作为「退出位」这个设计的来龙去脉：

第一版按五档设计时，off 写成了「不问、直接做，但开头标一行『假设：…』」——这其实还是本技能在管事。
用户指出：off 应该就是**不用 clarify-needs**。改了之后语义干净得多：

- 档位只剩 2 个**使用档**（high / max），off 是**技能退出位**，不是第 0 档
- off 下不留任何澄清痕迹：不复述、不问、不标假设、不做收尾钉住
- 「别问了 / 不用澄清 / 直接做」→ off，作用到本任务结束，下个任务重新定档
- 好处：不会出现「已经在 off 还硬要走流程」的四不像；也不会把「退出」误当成「最轻的锚定」

代价：off 变成一种绕过技能的通道。兜底是把它限定在纯查询、纯只读；会改文件/配置/系统的任务最低 high。

## 为什么删掉 M1–M3 模式

档位和模式是两套轴：档位说「问多深」，模式说「怎么问」。但两者实际高度相关——
high 就是「复述 + 选择题追问」，只有 max 才用设计树。两套轴的结果是每次都要交叉查表，
而表里只有一种有效组合。v3.0 直接把方法写进档位，`max` 独占设计树一节。

## 为什么合并 grilling

三个 grill 技能的真实内容：

| 技能 | 实际内容 |
|---|---|
| `grilling` | 31 行，设计树 + 轮次 + frontier（**唯一有实体**） |
| `grill-me` | 1 行：调 `grilling` |
| `grill-with-docs` | 1 行：调 `grilling` + `domain-modeling` |

后两个是转发壳，直接吸收不丢任何东西；`domain-modeling` 保留，max 要留档时调用。

**两处冲突的处理**：
1. grilling 要求「一轮问完整个 frontier」，原文要求「一次最多 3 题」 → **2026-10-23 定为一轮问完 frontier、题数不设上限**（用户：以质量为准，解除次数限制），只要每题都是决策题
2. grilling 只谈「挖想法」，原文只谈「确认需求」 → 用「档位差」区分：high 问需求，max 挖想法

## 锚定度怎么算

```
95% (high) = 核心路径与关键分叉已定，只剩实现细节
99% (max)  = 每步输入/输出/失败处理 + 边界/回滚/验收都定死，且每条分支都有结论
```

判据两条：
- 有一个判断是「我觉得应该是…」→ 不到 max
- 有一处「出问题再看」或「做完再说」→ 不到 max

不给这个定义，抬阈值只是换个数字自欺。

## 档名与推理 effort 撞名

`high / max` 同时也是模型推理 effort 的词。本技能的档说的是**锚定强度**（问用户多少），
推理 effort 说的是**想多久**（模型内部）。同名不同义，SKILL.md 末尾已显式提醒，
避免模型把「high 档」误解成「高推理」。

## 与 TG 的分工

TG 的原则 P3 是「过程指标不是结果」。本技能**连过程指标都没有**——无法证明「问对了更省」。
所以：
- 不并入 TG 的包（否则破坏 TG「1 常驻 + 6 待机」的结构）
- 只做接口引用：`tg-router` 里一行「需求不清 → 先走 clarify-needs」
- 若将来能量化「返工率」，再考虑合并（见 roadmap）

## 已知取舍

- **少一档会少一次判断**：三档里只有「要不要升 max」一个判断，用「用户可点名 + 默认 high」对冲，日常任务根本不显式定档
- **max 可能很长**：不设题数与轮次上限后，一次问完 frontier 可能十几题；靠「每题带推荐答案、回『是』即推进」和「只问决策题」压低负担
- **档位由模型自评**：可能判错；用户说「别问了 / 仔细点」可强制升降档
- **off 是绕过通道**：它是技能整体退出，不是「问得浅」；限定「只给纯只读」，会改文件/配置/系统的任务最低 high
